# The kernel owns each Goal's worktree and its branch

Vago runs each Goal's Steps in the Goal's own git worktree, outside the repo, under `$VAGO_HOME/worktrees/` (`~/.vago` by default). The worktree checks out `vago/<goal>`, which Vago cuts from the repo's default branch, and holds a copy of every untracked and ignored file of the main checkout except `.vago-goals/`: `node_modules/`, `.env` and local settings. It also gets the main checkout's `.vago/`, which is copied separately (see Consequences). Steps run there as they would in the main checkout, with no install Step. The kernel owns that worktree and that one branch. Every other git action stays the Workflow's: Ticket branches, commits, merges, pushes and PRs.

This supersedes ADR 0002, which kept the kernel free of git. With Steps in the human's checkout, the human couldn't touch it while a Goal ran, and two Goals couldn't run at once. A worktree per Goal costs a small amount of git in the kernel: one `git worktree add` per Goal and a few reads.

## Consequences

- The human may use the main checkout while Goals run, and its branch and files never change.
- Goal and Ticket state, `[[runs]]` and logs stay in the main checkout's `.vago-goals/`. A `vago` command started inside a Goal's worktree finds the main checkout, and shell Steps get its path in `VAGO_PROJECT_ROOT`.
- `.git/info/exclude` and git config are shared by every worktree of the repo.
- Running a Goal again reuses its worktree with the work in it. Untracked files are copied only when the worktree is created, except `.vago/`, tracked or not, which is copied again on every run with the human's uncommitted edits, so its scripts and prompts match the Workflow read from the main checkout. A worktree the human deleted, by `rm -rf` or `git worktree remove`, or that Vago removed once the Goal was done, is recreated from `vago/<goal>` with its commits and gets the untracked files copied again. To do that, Vago runs `git worktree prune`, which also clears git's record of any other worktree of the repo deleted by hand.
- After a `vago run` takes a Goal's last Tickets to done, Vago removes the worktree when it has no uncommitted changes and the remote has every commit of `vago/<goal>` and of the worktree's `HEAD`, as last fetched. A file the main checkout has with the same bytes at the same path, or a symlink with the same target, an ignored file and `.vago/` don't count as changes, so the copied files never block removal. Otherwise Vago keeps the worktree and prints why. A Goal that goes stuck keeps its worktree for the human to look inside. Branches and `.vago-goals/` are never touched.
- In the worktree, git never sees `.vago/` as a change. Its tracked files are marked skip-worktree in the worktree's own index, and a `.vago/.gitignore` written only there hides the rest, so a Workflow that commits everything never commits `.vago/`, and the main checkout's status still shows the human's edits. The cost: when another branch has a different tracked `.vago/`, merging, rebasing or switching onto it fails in the worktree with "local changes would be overwritten". A sparse checkout of `!/.vago/` avoids that, but it writes `extensions.worktreeConfig` into the repo's shared config and needs git 2.42, so it was rejected.
- `vago/<goal>` is cut with no upstream, so a Workflow's `git push` never aims at the default branch by accident.
- `VAGO_HOME` moves the folder, which the tests use to stay out of the real home folder.
- Goals of one Project run at once, one `vago run` per terminal, each in its own worktree. A second `vago run` of a Goal already running is refused, and a lock left by a killed `vago` is taken over.
